- Do not commit yourself unless the user asks for it.
- You're only allowed to work on the main branch, nowhere else.
- Do not write mock or fake code, or hardcode anything, everything must be production-ready and real, if you don't know what to do or pick, just go with the most production-ready option possible.
- UI work is governed by `frontend/DESIGN.md`. Read it first and use the Impeccable skill for design decisions.
- New UI composes `frontend/src/ui` primitives. Do not add raw palette values, one-off `rb-*` classes, or duplicate panel/button/dialog recipes in feature files. If a pattern is genuinely missing, add a primitive, document it in `frontend/DESIGN.md`, then use it.
- Run `npm run check:design` after UI changes. Only extend `scripts/design-system-baseline.json` for reviewed legacy code, never for new work.
- Definition of done for any code, contract, config, or script change: `npm run verify` must exit 0 before you report the task as finished. It runs the full CI matrix (format, design, lint, secret scan, Foundry format/build/test/gas snapshot/coverage, builds, typecheck, unit tests, generated-ABI drift, and the Playwright browser suite), so a green run means CI is green. Never report a task as done with a failing gate or with a gate you did not run. The only exception is a change that touches no source or test files: say so explicitly instead.
- `npm run verify` needs Foundry v1.9.0 and Playwright Chromium (`npx playwright install chromium` once per machine). The gate is enforced: `node scripts/verify-changes.mjs` runs verify once per change set, from `.husky/pre-push` and from the Codex `Stop` hook, so a red tree cannot be pushed or handed back.
- Do not use emojis anywhere, docs, frontend code, no where.
- Upon completing your work, spawn a subagent to do a full and thorough quality pass through it for any remaining bugs, issues or QoL improvements, but only if the change is large or high-risk, do not spawn it for simple work that you're sure is good enough.
- Make sure CI passes 100% before finishing.
- Once the work is final, send the owner a Telegram completion ping with `npm run notify:done -- --summary "<one line about what changed>"`. It reads the bot token and database credentials from `backend/.env` and messages the paired Telegram account. The ping is advisory: if it reports that no chat is paired or that delivery failed, mention that in your final message instead of retrying or blocking the task.
