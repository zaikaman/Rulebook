- Do not commit yourself unless the user asks for it.
- You're only allowed to work on the main branch, nowhere else.
- Do not write mock or fake code, or hardcode anything, everything must be production-ready and real, if you don't know what to do or pick, just go with the most production-ready option possible.
- UI work is governed by `frontend/DESIGN.md`. Read it first and use the Impeccable skill for design decisions.
- New UI composes `frontend/src/ui` primitives. Do not add raw palette values, one-off `rb-*` classes, or duplicate panel/button/dialog recipes in feature files. If a pattern is genuinely missing, add a primitive, document it in `frontend/DESIGN.md`, then use it.
- Run `npm run check:design` after UI changes. Only extend `scripts/design-system-baseline.json` for reviewed legacy code, never for new work.
- Definition of done for any code, contract, config, or script change: `npm run verify:fast` must exit 0 before you report a task as finished (plus targeted `npx playwright test <spec>` when changing UI/browser behavior, and `npm run verify` when requested, before pushing, or for contract/high-risk cross-cutting changes). `npm run verify:fast` runs format, design, lint, secret scan, full builds/typecheck, all unit tests, contract checks when `contracts/` changed, and any changed E2E specs. Full `npm run verify` runs the entire CI matrix including Solidity coverage and all Playwright browser specs. Never report a task as done with a failing gate or with a gate you did not run. The only exception is a change that touches no source or test files: say so explicitly instead.
- `npm run verify` needs Foundry v1.9.0 and Playwright Chromium (`npx playwright install chromium` once per machine). Both gates are enforced: `node scripts/verify-changes.mjs --fast` runs on the Codex `Stop` hook, and `node scripts/verify-changes.mjs` runs full `npm run verify` from `.husky/pre-push` so a red tree cannot be pushed.
- Do not use emojis anywhere, docs, frontend code, no where.
- Upon completing your work, spawn a subagent to do a full and thorough quality pass through it for any remaining bugs, issues or QoL improvements, but only if the change is large or high-risk, do not spawn it for simple work that you're sure is good enough.
- Make sure CI passes 100% before finishing.
- Once the work is final (after required verification passes), send the owner a Telegram completion ping with `npm run notify:done -- --summary "<one line about what changed>"`. It reads the bot token and database credentials from `backend/.env` and messages the paired Telegram account. The ping is advisory: if it reports that no chat is paired or that delivery failed, mention that in your final message instead of retrying or blocking the task.
